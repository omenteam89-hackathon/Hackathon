1. How to use this document in Antigravity Antigravity's agent works best when it gets the
whole context once, then builds in small, verifiable phases. Don't paste the entire PDF as
a single "build everything" prompt: the agent will skim and produce a shallow app.
1.1 Recommended workflow
1. Create an empty folder (e.g. anavandi-grievance) and open it as a workspace in
Antigravity.
2. Upload or drop this PDF into the workspace (or copy Sections 2–13 into a file called
SPEC.md at the project root). This becomes the agent's reference for every phase.
3. Paste the Master Context Prompt (Section 14.1) first. Ask the agent to produce an
implementation plan only and review it.
4. Run the phase prompts (Section 14.2) one at a time. After each phase, open the browser
preview, click through, and fix issues before moving on.
5. When the organiser's resource pack arrives, drop the CSV/JSON files into /public/data
and run the "Swap in real data" prompt (Phase 9).
6. Finish with the demo-hardening prompt and rehearse the demo script in Section 13.
1.2 Rules to give the agent at every step • Follow SPEC.md exactly; if something is ambiguous,
pick the simplest option and leave a // TODO(spec) comment. • Never hard-code organiser
data inside components. All data comes through the data layer (Section 6) so it can be
swapped. • Every screen must work at 360 px wide (phone) and at 1440 px (laptop / projector).
• Run npm run build and npm run lint at the end of each phase and fix all errors before
stopping. • Use the browser tool to open each new route and take a screenshot to verify it
visually.
Scope: This is a frontend-first build. All "backend" behaviour (routing, SLA
timers, escalation,
notifications) runs in the browser against a mock data layer with localStorage
persistence. That is
enough for a hackathon demo and is designed so a real API can be plugged in
later by replacing one
file (the repository layer).

6.3 SLA & escalation engine (sla.ts) All time comes from useClockStore.now(), never
Date.now(). This is what lets you fast-forward in the demo.
1. On create: ackDeadline = createdAt + rule.ackWithinHours, resolveDeadline = createdAt
+ rule.resolveWithinHours.
2. Effective deadline = deadline + slaPausedTotalMs (+ time since slaPausedAt if currently
AWAITING_INFO).
3. A tick() function runs every time the simulated clock changes. For each open complaint it
checks: – Not acknowledged and now > ackDeadline → escalate to next level. – Not
resolved and now > resolveDeadline → escalate to next level. – Already at L1 and now > L1
deadline (rule.escalateTo[1].afterHours) → escalate to L2.
4. Escalation = set status ESCALATED, increment escalationLevel, add timeline event, fire
notifications to passenger + new owner + depot.
5. Tick must be idempotent: running it twice at the same time must not double-escalate.

6. SLA state for UI: ok (> 25% left and > 2 h), warn (otherwise), breach (past deadline).

seconds and calls sla.tick(). • Always visible as SimClockBadge in the console header so judges
know the time is simulated.
